# Объяснение кода для защиты (уровень Junior)

## Коротко о проекте (можно рассказать преподавателю)

> Мой проект называется LocalGuard Junior. Это простое учебное приложение
> родительского контроля на WinForms. Оно проверяет текстовые файлы,
> показывает работу с системными процессами и имеет демо-чат с фильтром слов.
> Для обработки файлов я использовал асинхронность и до пяти параллельных задач.
> Чтобы несколько работников не мешали друг другу, я применил `Interlocked`
> и `lock`. Во время работы окно остаётся доступным, а прогресс виден на экране.

## Как устроены файлы

### Program.cs

- `Main()` — начало программы.
- `[STAThread]` — WinForms ожидает соответствующий режим главного потока.
- `ApplicationConfiguration.Initialize()` — стандартная настройка WinForms.
- `Application.Run(new MainForm())` — открывает окно и начинает цикл сообщений.

### MainForm.cs

- `Form` — обычное главное окно WinForms.
- `TabControl` — три вкладки: файлы, программы и чат.
- `CreateChatTab()` — создаёт поле ввода вверху и историю ниже (только для чтения).
- `SendChatMessage()` — фильтрует введённый текст и добавляет его в историю.
- Сам чат не запускает потоки: обработчик работает быстро прямо в UI-потоке.
- Кнопка проверки вызывает `ScanButton_Click`.
- `async void` допустим для **обработчиков событий** кнопок: он позволяет использовать `await`.
- `CancellationTokenSource` позволяет попросить фоновую задачу остановиться.
- `Progress<int>` передаёт процент в WinForms UI без прямого изменения контролов из рабочего потока.
- `Process.GetProcessesByName` получает запущенные программы по имени.
- `Process.Kill()` закрывает выбранный процесс; поэтому перед включением есть предупреждение.
- `Task.Run` выполняет цикл проверки программ вне UI-потока.
- `BeginInvoke` передаёт запись в журнал обратно в UI-поток.

### TextFilter.cs

- `ParseWords` превращает строку `дурак, грубость` в список слов.
- `Regex.Escape` нужен, чтобы специальные символы воспринимались как текст.
- `Regex.Replace` находит слова и заменяет каждую букву на `*`.
- `Count` считает число замен.
- Обрабатываем только введённый текст и текстовые файлы; это не перехват чатов.

### FileScanService.cs

- `Directory.EnumerateFiles(..., EnumerationOptions)` ищет текстовые файлы в папке и подпапках.
- `Parallel.ForEachAsync` обрабатывает разные файлы параллельно.
- `MaxDegreeOfParallelism = 5` ограничивает число одновременно работающих задач.
- `File.ReadAllTextAsync` и `File.WriteAllTextAsync` — асинхронный ввод-вывод.
- `Interlocked.Increment(ref processed)` увеличивает общий счётчик **атомарно**:
  два работника не смогут потерять увеличение.
- `lock (listLock)` защищает общий `List<ScanMatch>`, в который пишут работники.
- `Path.GetRelativePath` сохраняет структуру подпапок в копии.
- `report.txt` создаётся после завершения работников.

## Почему окно не зависает?

> Долгая работа идёт асинхронно. `await` позволяет интерфейсу продолжать
> отвечать на нажатия кнопок. Прогресс изменяется через `Progress<int>`,
> а не прямым вызовом из чужого потока.

## В чём разница между процессом и потоком?

> Процесс — отдельная запущенная программа. У него собственное адресное пространство.
> Поток — путь выполнения кода внутри процесса. В одном процессе может быть много потоков.

## Зачем Interlocked, если есть lock?

> `Interlocked` нужен для одной простой операции: безопасно прибавить 1.
> `lock` удобнее, когда надо защитить несколько операций со списком.
> Здесь показаны оба способа синхронизации.

## Зачем CancellationTokenSource?

> Нажатие «Остановить» вызывает `Cancel()`. Фоновые операции получают сигнал
> и прекращают работу без `Thread.Abort`.

## Почему нельзя менять progressBar прямо из Task.Run?

> Элементы WinForms принадлежат UI-потоку. Поэтому мы используем `Progress<int>`
> для проверки файлов и `BeginInvoke` для журнала процессов.

## Почему не Windows API (P/Invoke)?

> .NET уже предоставляет классы Process, File и Directory. В ТЗ P/Invoke
> рекомендуется только при реальной необходимости. Здесь её нет.

## Что показать преподавателю за 3–5 минут

1. Запустить готовый проект через `dotnet run --project .\LocalGuardJunior.csproj`.
2. На вкладке «Файлы» проверить папку `examples` и открыть отчёт.
3. Показать в `FileScanService.cs` пять работников, `Interlocked` и `lock`.
4. Открыть пустой Блокнот и показать контроль процесса `notepad`.
5. В демо-чате ввести запрещённое слово и показать замену на `*`.
6. Рассказать, что исходные файлы не переписываются и чужие переписки не читаются.
